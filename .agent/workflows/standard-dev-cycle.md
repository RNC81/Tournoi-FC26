ANALYSE : L'Orchestrateur sollicite Security_Auditor pour évaluer l'impact d'une demande sur le server.py et le PROJECT_MANIFEST.md (ton nouveau nom pour la doc).

PLANIFICATION : L'Orchestrateur demande à Dev_Specialist de lister les fichiers à modifier ET les variables d'environnement nécessaires.

EXÉCUTION : Dev_Specialist applique les changements.

REVUE : Security_Auditor valide que le code respecte les Workspace Rules (ports, regex, etc.).

SYNTHÈSE : Scribe_Technique met à jour la doc avec une section "Human-Friendly" en haut de page.

REPORT : L'Orchestrateur fait un topo final à l'utilisateur : "Ce qui a changé, pourquoi, et quel port checker".
